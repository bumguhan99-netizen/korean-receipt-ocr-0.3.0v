# 영수증 OCR 데이터셋 재라벨링 계획

2026년 11월 20일 · 대상은 `ocr_v3`에 준비한 스마트폰 영수증과 KORIE 원본이다. 작업을 배정할 때는 [재라벨링 작업 지시문](<OCR_영수증_재라벨링_작업지시문_20261120.md>)을 함께 전달한다.

**먼저 손볼 곳은 품목 단가·수량 열, 스마트폰 한글 품목명, 기존 크롭에서 잘리거나 빠진 줄이다.** 영수증마다 원본 전체를 한 번 읽고, 사람이 읽을 수 있는 한 줄 또는 표의 한 셀을 크롭 하나와 전사 하나로 연결한다. 새 라벨의 효과는 학습률을 고정한 대조 실험으로 확인한다.

## 학습률과 인식 성능에서 확인한 사실

학습률(LR)은 한 번에 가중치를 얼마나 갱신할지 정하는 설정값이다. v1 KORIE 2차는 1차의 `1e-5`를 재사용했고, v2 스마트폰 단계도 v1 채택 조건을 재현하는 설정에서 `1e-5`를 사용했다. v2 S1의 동일한 BN 갱신 조건에서는 LR `3e-5 / 1e-4 / 3e-4`별로 보호 조건을 통과한 후보가 각각 **0/30, 7/30, 21/30**이었다. 이는 당시 선택 규칙의 통과 수다. 작은 배치에서는 배치 정규화(BN)의 이동 통계만 복원해도 검증 CER이 **39.85% → 32.56%**로 변했다. 따라서 낮은 인식 성능 중 라벨에 기인한 부분을 판단하려면 LR·BN·데이터 구성을 통제해야 한다. |---|---|---|

두 작업자가 파일럿 12장을 독립 판독한다. 한 명이 작업하면 2차 판독 때 1차 결과를 숨기고 자기 재검수로 표시한다. 자기 재검수는 독립 판독 일치율과 구분해 집계한다. 결과를 겹쳐 **누락 줄, 줄·셀 분할 차이, 숫자·부호, 공백·문자, 필드 해석** 순으로 조정한다. 판정 예시에는 train 사진만 쓴다. 파일럿에서 장당 초벌·검수 시간을 따로 기록해 남은 물량을 산정한다.

## 3. 본 작업과 인수 기준

| 순서 | 실행 방법 | 완료 기준 |
|---|---|---|
| 원본 전수 표시 | 배정된 원본을 정상 읽기 방향으로 열고 전체 글줄을 표시한다. 표는 상품 행을 연결하고 각 셀을 나눈다. 영역 검출용 좌표와 판독용 전사를 각각 남긴다. | 모든 원본에 전체 확인·부분 확인·접근 불가 상태가 있다. 원본 전체 평가용은 별도 검수자가 전체 화면에서 누락 여부를 확인한다. |
| 전사와 재크롭 | 1차에는 원본과 새 크롭만 보고 입력한다. 2차에 기존 라벨을 대조한다. 한 글자라도 잘렸으면 원본에서 다시 자르고, 원본에서도 읽을 수 없으면 사유를 남긴다. | 실물에 보인 전사, NFC 파생값, 원본 좌표, 새 크롭 해시가 연결된다. 부모 표 영역과 자식 셀이 학습 목록에 겹쳐 들어가는 건은 0개다. |
| 이중 검수 | 학습에 넣을 모든 후보는 사람이 최소 한 번 원본과 크롭을 대조한다. 금액·수량·할인 부호, 전사 충돌, 실제 여러 줄, 불확실·복구 건은 전수 재확인한다. 일반 줄은 출처별 10%를 무작위 재검수한다. 평가용 원본은 예측을 가리고 판독한다. | **제안 기준**은 일반 이중 검수 표본의 판정 전 문자열 EM ≥98%, 최종 승인 목록의 미해결 숫자·부호 충돌 0건이다. 표본 수와 불일치 건수를 함께 보고한다. 기준 미달이면 해당 출처·오류 유형의 검수 범위를 넓힌다. |
| 학습·평가 목록 생성 | 학습 목록에는 train의 승인된 판독 가능 크롭 중 인코더 통과분을 넣는다. OOV, 긴 줄, CTC 정렬 제약은 전사를 보존하고 별도 사유로 기록한다. | 분할 간 거래·동일 크롭 교차 0건, 승인 전사와 크롭 파일 누락 0건. 각 줄의 원래 분할은 유지한다. train 보류분은 train 감사표에, 검증·test의 읽을 수 있는 긴 줄과 사전 밖 문자는 각각 같은 분할의 외부 평가 분모에 남긴다. |

이중 판독 EM은 같은 영역으로 매칭한 줄 중 NFC 전사가 완전히 같은 줄 수를 두 사람이 모두 판독한 줄 수로 나눈다. 한쪽만 표시한 영역은 누락·과분할·미분할로 별도 집계한다. 분모가 0이면 측정 불가로 적는다.

현 설정의 `max_text_length=25`에서 v2 전처리는 24~25자를 NRTR 제한, 25자 초과를 길이 보류로 처리했다. 세로로 겹친 두 줄은 나누되, 긴 한 줄을 길이 제한에 맞춰 임의 절단하거나 인쇄 문자를 치환하지 않는다. [현재 학습 설정][yaml] · [기존 인코더 검사][encoder]

**저장 규약.** 향후 작업 폴더는 `ocr_v3/data/relabel_<날짜>_rNN/`처럼 새 버전으로 만든다. 원본 등록표, 영수증별 초벌·검수 기록, `crops/`, `issues.csv`, `qa_summary.json`을 같은 버전에 둔다. `train.txt`와 `validation.txt`에는 프로젝트 상대 크롭 경로와 NFC 전사를 탭 하나로 연결한다. 학습 가능 표본만 담은 내장 검증 목록과 읽을 수 있는 전체 줄의 외부 평가 목록을 따로 저장한다. 개봉 전 test는 별도 경로에 봉인한다.

## 4. 재라벨링의 효과를 판정한다

1. **정답 수정 효과.** 같은 검증 크롭과 저장된 예측으로 구·신 전사를 각각 채점한다. 1,592줄 재채점처럼 분자(편집 수)와 분모(정답 문자 수)를 병기한다. 이 차이는 평가 기준을 바로잡은 효과다.
2. **학습용 전사 개선 효과.** 동일 train ID·동일 크롭에서 옛 전사와 새 전사만 바꿔 두 번 학습한다. 초기 공식 가중치, LR(현재 템플릿 1e−4), BN, 샘플 구성, 총 업데이트 수, seed, 외부 추론 배치 1을 맞춘다. 두 모델 모두 **같은 새 검증 정답**에서 스마트폰 한글 줄 CER, 단가·수량·실결제액 EM을 비교한다. 실결제액은 같은 원본 검출·필드 추출 설정으로 영수증 단위에서 채점한다.
3. **줄 분할·누락 복구 효과.** 인식기를 고정해 옛 크롭과 새 크롭을 같은 원본에서 읽는다. 재분할로 자식 수가 바뀌면 같은 부모 영역의 전사와 읽기 순서로 비교한다. 원래 누락됐던 줄은 별도 집계하고 전체 원본의 누락률도 보고한다. 차이의 불확실성은 영수증·거래 그룹 단위로 계산한다. 최종 외부 평가는 모델과 정책을 동결한 뒤 한 번 수행한다.
