# 한국어 영수증 OCR 실험 결과와 재학습 개선안

2026년 11월 20일 · 대상은 스마트폰으로 촬영한 영수증의 글줄·금액 인식이다. `ocr`의 v1 원실험, `ocr_v2`의 모델 교체·정산 검증, `ocr_v2_retrain`의 7개 재학습 실험, `ocr_v3`의 원본과 설정을 기준으로 작성했다.

## 다음 학습에서 먼저 바꿀 것

1. **원본 영수증 단위로 평가 대상을 먼저 고정한다.** v2 스마트폰 검증 61장 중 **40장**이 v1 스마트폰 인식기의 학습 영수증이었다. 검증 1,592줄 중 **865줄**은 v1 학습 크롭과 파일 내용까지 같았다. 모델 교체 여부는 두 모델 모두 학습에서 보지 않은 거래 그룹에서 판단한다. [v1 학습 목록][v1-train] · [v2 검증 목록][v2-phone-val]
2. **새 크롭에서 한 줄씩 전사를 확정하고 단가 열부터 검수한다.** v1의 사용자 검수본과 v2 학습에 사용한 스마트폰 라벨은 같은 8,343개 크롭 중 **418개**에서 달랐다. KORIE에서는 세로형 크롭 **15.0%**에 v2 S1 편집 오류의 **59.4%**가 몰렸다. 정답 버전, 실제 줄 경계, 읽는 순서를 바로잡는 작업이 첫 번째 비교 실험이다. [스마트폰 검수 이력][review] · [v2 라벨 원본][old-labels] · [S1 오류 집계][s1-korie]
3. **공식 사전학습 가중치에서 시작해 첫 epoch부터 스마트폰과 KORIE를 함께 검증한다.** KORIE로 먼저 학습한 v2 S1은 단일행 CER을 개선했지만 스마트폰 CER이 **7.496% → 16.442%**로 올랐다. 이후 스마트폰을 섞은 S2에서도 40개 후보 모두 보호 조건을 넘었다. 다음 실험은 동일한 학습량에서 ‘KORIE만’과 ‘처음부터 혼합’을 비교한다. [v2 실행 결과][v2-report] · [S2 선택 기록][s2-select]

## 1. v1은 스마트폰 글줄을 잘 읽게 됐지만 원본 사진에서 줄을 놓쳤다

**CER**은 NFC 정규화 후 문자 삽입·삭제·치환 수의 합을 전체 정답 문자 수로 나눈 값이다. 낮을수록 좋다. **EM**은 공백과 구두점까지 완전히 같은 문자열의 비율로, 높을수록 좋다. 아래의 금액 EM은 총액·소계·세금·단가·품목 합계 **크롭**의 문자열 EM이다. 영수증 한 장에서 결제금액을 찾아내는 정확도는 별도 평가한다.

| KORIE 공식 크롭 | 검증 CER ↓ | 검증 EM ↑ | test CER ↓ | test EM ↑ | test 금액 EM ↑ |
|---|---:|---:|---:|---:|---:|
| 한국어 공식 가중치의 초기 export | 30.87% | 54.57% | 28.37% | 53.98% | 52.14% |
| v1 KORIE 1차 | 23.96% | 71.71% | 21.16% | 71.56% | 77.22% |
| v1 KORIE 2차 · epoch 5 | 23.35% | 74.34% | **20.70%** | **73.46%** | 77.58% |
| v1 스마트폰 최종 · Claude run_001, epoch 15 | 25.09% | 71.37% | 22.33% | 71.72% | **78.11%** |

검증은 1,785개, test는 1,786개이며 test 금액 표본은 562개다. 튜닝 전 같은 검증 크롭에서 범용 PP-OCRv5 mobile의 CER은 44.27%, 한국어 모델은 30.87%, GLM-OCR은 17.43%였다. PP-OCR 두 모델은 CPU, GLM은 GPU에서 평가했다. 이후 프로젝트는 경량 한국어 모델을 선택했다. [초기 모델 비교][model-choice] · [1차 결과][round1] · [2차 검증][r2-val] · [2차 test][r2-test] · [스마트폰 최종 test][v1-test] · [최종 모델의 KORIE 검증][v1-ref-k]

![v1 KORIE 2차와 스마트폰 최종 모델의 문자 오류율. 스마트폰 정답 크롭은 7.46%에서 2.81%, 원본 부분 평가는 20.04%에서 16.26%, KORIE 크롭은 20.70%에서 22.33%로 변했다.](figures/01_v1_test.png)

같은 스마트폰 내부 test 51장·1,423줄에서 **정답 크롭 CER은 7.462% → 2.811%**였다. 영수증 단위 짝지은 bootstrap의 차이는 −4.651%p(95% 구간 −5.581~−3.808%p)였다. 반면 KORIE 공식 test 차이는 +1.634%p(+1.112~+2.144%p)였다. Claude 경로는 4개 run의 80개 후보 중 스마트폰용 모델을 선택했고, Antigravity 경로는 별도 보호 조건에서 15개 후보가 모두 탈락해 2차 인식기를 유지했다. Claude run_002의 검증 최저 CER 2.261%와 run_001의 2.283%가 사전 동률 범위 0.05%p 안에 들어 더 이른 epoch 15를 선택했다. [동결 후 평가][v1-test] · [두 경로의 최종 선택][v1-final]

**원본 사진에서는 검출 누락이 더 크게 남았다.** 같은 검출 캐시의 공통 평가에서 스마트폰 최종 모델의 CER은 16.262%였다. 두 인식기가 똑같이 놓친 정답 **138줄·1,358자**가 전체 정답 14,728자의 **9.22%p**에 해당한다. 미매칭 정답은 삭제로 채점했고 남는 예측은 미채점이므로, 이 평가는 라벨이 있는 줄에 대한 부분 평가다. 51장도 이전 검출 진단에 사용한 304장에서 나눈 내부 집합이다. [원본 평가와 매칭 범위][v1-full]

## 2. v2에서 어느 단계가 좋아졌고 왜 최종 후보가 없었나

### S1에서 단일행은 개선됐고, 세로형과 단가 열에 오류가 집중됐다

S1은 KORIE 단일행으로 5개 run을 각 30 epoch 학습했다. 150개 후보 중 보호 조건을 통과한 수는 아래와 같다. S1-E의 단일행 CER은 v1 2차보다 **1.588%p 낮았다**(95% 구간 −2.081~−1.131%p). 반면 선택 규칙에서 스마트폰 성능은 기록만 했기 때문에 S1-E의 스마트폰 하락을 걸러내지 못했다. [후보별 판정·bootstrap][s1-select] · [v2 실행 설정][v2-report]

| S1 실험 | 학습률 · BN 통계 | 비교한 변경 | 보호 통과 / 30 | run 안에서 고른 epoch | 단일행 / 스마트폰 CER |
|---|---|---|---:|---:|---:|
| A | 3e−5 · 갱신 | 낮은 학습률, 정답 뒤에 문자가 붙는 현상 빈발 | 0 | 없음 | — |
| B | 1e−4 · 갱신 | 학습률 변경 | 7 | 17 | 12.052% / 11.002% |
| C | 3e−4 · 갱신 | 학습률 변경 | 21 | 30 | 11.241% / 14.895% |
| D | 3e−4 · 고정 | C 대비 배치 정규화(BN) 통계만 고정 | 30 | 25 | 12.263% / 21.072% |
| E | 3e−4 · 갱신 | C 대비 문자열 연결 증강(RecConAug) 끔 | 19 | 29 | 11.162% / 16.442% |

![v2 S1 KORIE 검증에서 세로형이 차지하는 비율. 크롭의 15.0%, 정답 문자의 17.2%, 문자 편집 오류의 59.4%.](figures/02_korie_error_share.png)

세로형 268개에서 편집 오류가 **2,480건**, 나머지 1,517개에서 **1,694건** 발생했다. 금액 필드만 보면 **품목 단가**가 1,645건 중 **1,234건(75.0%)**을 차지했다. 단가 EM은 42.42%(132개), 총액 EM은 96.83%(126개)였다. 다음 라벨링에서는 상품별 단가·수량이 세로로 배열된 영역과 가로 두 줄 주소를 우선 확인한다. 같은 영역을 줄별로 다시 검출한 과거 P4 실험에서 v1 2차의 세로형 CER은 **74.52% → 32.32%**, 전체는 **23.35% → 16.11%**였다. 같은 검증 집합에서 정한 정책이라 새 영수증에서 재검증할 가치가 있다. [S1 필드별 오류][s1-korie] · [P4 분할 진단][p4]

### S2에서 스마트폰을 회복해도 세로형 오류는 허용치를 넘었다

![S2 두 run의 epoch 0~20 실제 검증 CER. 스마트폰 오류는 줄어들지만 KORIE 세로형 CER은 학습 후 매 epoch에서 허용 상한 81.88%를 초과했다.](figures/03_v2_s2_epochs.png)

세로형 허용 상한은 **81.880%**(S1의 78.880% + 3.0%p)였다. S2-A 20개 epoch의 세로형 CER은 84.510~88.168%, S2-B의 20개는 84.892~89.885%였다. S2-B epoch 16은 스마트폰 CER을 4.413%까지 낮췄지만 세로형 CER 86.355%로 탈락했다. 이 결과만으로 혼합 비율의 효과를 분리하기도 어렵다. 두 run 모두 학습률 1e−5, BN 고정이었지만 A는 약 148 step/epoch, B는 약 275 step/epoch였다. B의 두 학습 목록은 스마트폰 4,754줄과 KORIE 4,070줄을 각각 전량 사용했다. 또 S1-E에서 껐던 RecConAug가 두 S2 run에서 0.5로 돌아왔다. [S2-A 설정][s2a-spec] · [S2-B 설정][s2b-spec] · [시점별 외부 평가][s2-history] · [보호 조건][rules]

## 3. 새 데이터셋을 만들 때 바로잡아야 할 두 가지

### 검증 목록을 바꿔도 같은 영수증이 다시 들어올 수 있다

v1 스마트폰 분할은 train/val/test **202/51/51장**, v2는 **182/61/61장**이다. v2 검증 61장을 v1 그룹에 연결하면 **v1 train 40장, val 9장, test 12장**이다. 40장에서 온 v2 검증 줄은 973개이며, 그중 865개는 v1 학습 목록에 있는 같은 이름의 크롭과 SHA-256까지 일치했다. v1 최종의 v2 검증 CER 3.452%와 S2-B의 4.413% 차이를 새 영수증에 대한 우열로 해석하기 어렵다. [v1 그룹 배정][groups] · [v1 학습 크롭][v1-train] · [v2 검증 크롭과 해시][v2-phone-val]

KORIE 공식 크롭에는 train↔val **155개**, train↔test **149개**, val↔test **52개**의 동일 이미지 해시가 있었다. v2는 train에서 해당 304개 표본을 뺐고 공식 val/test 분모는 보존했다. 새 실험도 공식 점수는 과거와의 대조용으로 남기고, 모델 교체에는 원본 거래까지 추적되는 별도 평가 집합을 쓴다. 공식 크롭과 원본의 `IMGxxxxx` 번호만으로 같은 거래나 글줄을 단정할 수 없다. [중복 감사][dups] · [원본–크롭 ID 대조의 한계][k-id]

### 정답 버전만 바꿔도 같은 예측의 CER이 달라진다

v1 후반의 사용자 검수본 `phone_label_review_20261117_v3`와 `ocr_v2_retrain`의 `recognition_verified.txt`를 크롭 파일명으로 연결했다. NFC 적용 후 **418/8,343줄**의 전사가 달랐고, 395줄은 공백 외 문자도 달랐다. v2 검증에서는 **72/1,592줄**이 달랐다. 아래는 저장된 예측 문자열을 그대로 두고 이 1,592줄의 정답만 바꿔 계산한 값이다. 여기서 ‘검수본 v3’는 라벨의 버전명이다. [사용자 검수 기록][review] · [검수본 전사][new-labels] · [v2 전사][old-labels]

| 고정한 스마트폰 예측 | v2 당시 정답으로 CER | 검수본 v3 정답으로 CER |
|---|---:|---:|
| 공식 사전학습 | 1,240 / 16,543 = 7.496% | 1,145 / 16,537 = 6.924% |
| v1 스마트폰 최종 | 571 / 16,543 = 3.452% | 474 / 16,537 = 2.866% |
| v2 S1-E epoch 29 | 2,720 / 16,543 = 16.442% | 2,659 / 16,537 = 16.079% |
| v2 S2-B epoch 16 | 730 / 16,543 = 4.413% | 638 / 16,537 = 3.858% |

분자는 문자 편집 수, 분모는 해당 버전의 정답 문자 수다. S2-B의 **0.555%p 차이**는 라벨에 따른 측정 차이다. 새 학습의 점수, 과거 S2 탈락 판정, 데이터 노출 여부와는 별개다. 앞으로는 모든 기준 모델을 동일한 새 정답으로 채점하고 라벨 해시를 점수 옆에 저장한다. [공식 초기 예측][pred0] · [v1 최종 예측][pred1] · [S1-E 예측][pred-s1] · [S2-B 예측][pred-s2]

## 5. 무엇을 어떤 순서로 학습할 것인가

아래 설정과 허용치는 **새 실험을 시작하기 전 고정할 제안값**이다. `ocr_v3/training.yaml`의 출발점은 공식 `korean_PP-OCRv5_mobile_rec`, epoch 30, 학습률 1e−4, 기준 배치 32, seed 42, RecConAug 0, 길이 25다. 공식 가중치 SHA-256은 `8975dede…d52a3`, 사전은 `2193f5dd…72828`이다. 과거 튜닝 모델은 비교용으로 불러오고 새 가중치 학습은 이 공식 체크포인트에서 시작한다. [현재 v3 설정][v3-config] · [공식 모델 설정][paddle-upstream]

| 순서 | 비교 실험 | 고정할 조건과 판단할 질문 |
|---|---|---|
| 0. 기준선·스모크 | 새 검증 목록에 공식 모델, v1 KORIE 2차, v1 스마트폰 최종, v2 S1-E를 평가한다. 소량의 train/val로 로딩→학습→export→재추론을 한 번 통과시킨다. | 외부 추론 배치 1, 사전·리사이즈·디코더·NFC를 고정한다. 기존 KORIE 공식 검증을 재현할 때 초기 CER **30.8679%**가 대조점이다. 새 분할에는 새 기준값을 쓴다. |
| A. KORIE 대조군 | 새로 검수한 KORIE 단일행으로 학습한다. | B와 동일한 초기 가중치, LR, BN 갱신, 증강, sampler step 수를 사용한다. 스마트폰 지표도 첫 epoch부터 기록한다. |
| B. 처음부터 혼합 | 같은 초기 모델에서 스마트폰과 KORIE 단일행을 **추출 횟수 기준 1:1**로 학습한다. | A와의 차이는 도메인 구성이다. epoch당 optimizer 128회 × 최대 30 epoch를 공통 예산으로 두고 두 도메인의 실제 소비 줄 수를 기록한다. |
| C. 검수한 여러 줄 영역 활용 | B의 KORIE 추출분 일부를 단가·수량·주소 등에서 사람이 나눠 전사한 줄로 교체한다. | 혼합 비율·총 step·LR을 B와 맞춘다. B와 C 양쪽에 같은 분할 정책을 적용해 부모 영역 단위 재조합 CER과 원래 단일행 성능을 함께 본다. |
| D. 원본 파이프라인 | 선정한 인식기와 검출 캐시를 고정한 뒤 영역 내부 줄 분할을 끔/켬으로 비교한다. | 학습 가중치를 고정해 전처리 효과를 측정한다. 가격·수량 열의 읽기 순서, 한 자리 숫자 과분할, 누락 정답 줄, 처리시간 p95를 확인한다. |

**학습 중 확인할 것.** 작은 배치에서 BN 통계만 되돌린 v2 스모크는 검증 128줄 CER이 39.85%에서 32.56%로 회복됐다. 반대로 BN을 전부 고정한 S1-D는 스마트폰에서 약했다. 우선 BN 갱신 설정을 고정하고, 흔들림이 재현되면 같은 데이터·시드로 BN 통계 고정만 바꾼 대조군을 만든다. 외부 평가에서는 KORIE 검증 1,785개 중 배치 1과 64의 예측이 **376개** 달랐으므로 비교·서비스 재현에 배치 1을 쓴다. 학습 중 배치 64로 측정한 내장 정확도는 진단용으로 기록한다. [BN·추론 배치 대조][v2-lessons] · [서로 다른 예측 목록][batch-diag]

**실행 경로.** 데이터 목록이 준비되면 `ocr_v3`의 Compose 서비스를 사용한다. A/B/C마다 설정을 복사해 train 목록과 `save_model_dir`를 서로 다른 새 run 경로로 지정한다. 예를 들어 B의 설정을 `ocr_v3/configs/mix_01.yml`로 작성한 뒤, `ocr_v3`에서 `docker compose run --rm train python tools/train.py -c /workspace/configs/mix_01.yml`로 실행한다. 현재 YAML의 기본 실행은 내장 평가까지만 연결돼 있다. 각 epoch의 export와 외부 채점에는 v2 평가 코드를 새 목록·새 경로에 맞춰 연결한다. ### 채택과 최종 평가

- **검증 집합을 두 용도로 쓴다.** 학습 중에는 개발용 검증 집합에서 매 epoch의 스마트폰·KORIE CER/EM, 세로형, 긴 줄, 금액·숫자 EM, 빈 출력, 정답 뒤 덧붙임 비율을 기록한다. 독립 확인용 검증 그룹은 후보를 좁힌 후 한 번 사용한다. 과거 모델 교체를 판정할 그룹은 그 모델의 train 그룹과도 교차하지 않게 선정한다.
- **후보 선택 기준을 사전 등록한다.** 인식기 주 지표는 스마트폰 줄 CER이다. 같은 새 검증셋에서 v1 스마트폰 최종 대비 차이의 영수증·거래 그룹 단위 paired bootstrap 95% 상한이 0 미만인 후보를 남긴다(2,000회, seed 고정). KORIE는 v1 2차를 고정 기준으로 삼아 단일행 CER 상승 ≤0.50%p, 세로형 CER 상승 ≤3.00%p, 금액 EM 하락 ≤1.00%p, 단일행 숫자·기호 EM 하락 ≤1.00%p를 동시에 확인한다. 기준을 통과한 후보끼리 CER 차이가 0.05%p 이내면 이웃 epoch의 스마트폰 최저 EM이 높은 쪽을 고른다.
- **원본 사진에서 교체를 확인한다.** 같은 사진·검출 박스에서 인식기만 바꾼 결과와, 검출부터 다시 실행한 결과를 각각 남긴다. 전체 줄을 검수한 새 사진에서 검출 precision/recall, 원본 줄 CER, 영수증별 실제 결제금액 EM을 보고한다. 제안하는 서비스 채택 조건은 기존 스마트폰 파이프라인 대비 원본 줄 CER 개선과 결제금액 EM 유지 이상이다. 부분 라벨 집합은 과거와 같은 IoU ≥0.5 일대일 매칭으로 별도 집계한다. [기존 부분 평가 정의][v1-full] · [외부 필드 정의][outside-fields]
- **최종 test는 동결 후 1회다.** 모델·사전·코드·컨테이너·라벨·분할·전처리 해시와 판정 규칙을 먼저 저장한다. test 결과는 원본 장수, 거래 그룹 수, 줄 수, 정답 문자 수, 지표 차이와 구간을 함께 남긴다. 통과 후보가 없으면 기준 모델을 유지하고 실패한 조건을 기록한다. 과거 개발에 노출된 304장만으로는 새 매장·촬영 환경 일반화를 확인하기 어려우므로 신규 촬영분을 별도 봉인하는 편이 좋다.
