# 영수증 OCR 재라벨링 결과 · r02

학습·검증 영수증 219장에서 **줄·셀 293개의 라벨을 변경했다.** 이 중 186개는 판독 대기 또는 재크롭에서 전사 가능한 초안으로 바뀌었다. 반대로 기존 전사 11개는 글자가 잘리거나 판독이 모호해 보류했다. 새 크롭 13개를 원본 좌표와 함께 반영했다. 변경 단위마다 이전 값과 새 값을 대조할 수 있다. [변경 이력](../data/relabel_20261120_r02/changes.csv)

JSONL의 한 행은 영수증 한 장이다. `units`의 `quad`는 EXIF 방향을 적용한 원본의 네 꼭짓점(픽셀)이다. `image_path`와 `crop_path`는 `ocr_v3/` 기준이다. 기존 크롭은 r01 파일을 참조하므로 **r01과 r02를 함께 보관한다.** 분할별 JSONL은 격리 영수증까지 추적하며, 사용 가능한 행은 `effective_split`이 해당 분할인 행이다. [원본·거래 그룹 등록표](../data/relabel_20261120_r02/receipts.csv)

## 실제 작업 범위

원본은 스마트폰 304장, 추가 영수증 52장, KORIE 774장으로 총 **1,130장**이다. 전처리한 기준 프레임과 크롭 63,127개의 좌표·파일 연결을 확인하고, 원본·프레임·크롭 파일 총 65,387개의 SHA-256을 대조했다. 기존 등록표에서 같은 거래가 여러 공식 분할에 걸친 KORIE 6장은 격리를 유지했다. 사용 대상 거래 그룹의 분할 교차는 0건이었다. [입력 검증](../data/relabel_20261120_r02/input_verification.json)

직접 대조, 기계 판독, 변경, 재크롭은 서로 겹친다. 변경 수는 고유한 영수증 ID와 단위 ID를 기준으로 셌다. 기존 테스트 218장과 외부 평가 23장(20거래 그룹)의 라벨은 봉인 상태로 이관하고 파일 해시가 r01과 일치하는지 확인했다. 이번 직접 판독은 학습·검증 크롭과 필요한 원본 주변 영역에 한정했다. r01에서 원본 전체를 대조한 13장과 부분 대조한 1,117장의 범위 표기를 유지했다. [분할별 최종 검증](../data/relabel_20261120_r02/release_verification.json)

## 무엇을 고쳤나

- **할인 부호와 금액 필드.** 크롭에서 음수 부호와 천 단위 쉼표를 확인해 할인액을 전사했다. ‘신용카드지불’, ‘받 은 돈’처럼 숫자 없이 제목만 보이는 크롭은 금액값으로 쓰이지 않도록 필드를 고쳤다.
- **상품명과 크롭 경계.** 스마트폰 영수증에서 상품명으로 분류된 96개를 다시 읽었다. 이웃 줄이 섞이거나 숫자 뒤 구두점이 모호한 항목은 보류했다. 잘린 ‘솔티 초코 소금빵’과 ‘너티아메리카노HS’는 원본에서 꼭짓점을 다시 잡았다. [1차 크롭 비교 이미지](../data/relabel_20261120_r02/visual_review/selected_recrops.png) · [원본에서 다시 그린 크롭](../data/relabel_20261120_r02/visual_review/traced_recrops.png)
- **단가와 바코드 구분.** `IMG00673/u0095`는 바코드 아래에 숫자가 인쇄된 영역이었다. 번호 한 줄을 다시 잘라 `barcode_text`로 기록했다. 가격 통계와 단가 평가에서 제외할 수 있다. [변경 이력](../data/relabel_20261120_r02/changes.csv)
- **기계 재판독.** 격리 제외 학습·검증에서 기존 판정이 `undecided`·`recrop`이거나 검수가 필요했던 단위를 모두 로컬 한국어 PP-OCRv5로 다시 읽었다. 이전 판독 문자열과 일치하고 점수 0.95 이상이며 숫자·부호 등 보류 규칙을 통과한 62개에만 기계 근거로 전사 후보를 넣었다. 해당 줄은 모두 `needs_review`다. 원래 문자열이 있던 6,686개 중 새 모델과의 완전일치는 1,920개였다. 이는 충돌 중심 표본에서의 판독 간 일치 수다. [집계](../data/relabel_20261120_r02/release_counts.json)

## 검수와 재학습 인계

1. 파일럿과 금액·수량·할인, 충돌 건부터 각 분할의 검수 목록을 연다. 검수자는 `frame_path`에서 먼저 독립 전사를 적고 `crop_path`와 대조한다. 변경 이력이 있는 단위는 JSONL의 `r02_previous`에서 이전 전사·좌표·해시까지 확인할 수 있다.
2. 학습 4,183개와 검증 1,421개의 판독 대기 중 글자가 모호하면 수치를 추정하지 않고 판정을 남긴다. 재크롭 대기 56개는 원본에서 이웃 줄과 글자 끝을 확인한다. 우선순위 목록에는 이들 외에 정상으로 읽힌 금액 필드와 일반 줄 표본도 포함된다. [작업 지시문](OCR_영수증_재라벨링_작업지시문_20261120.md)
3. 사람이 원본과 크롭을 확인해 승인한 뒤, 승인자·시각·해시를 다음 버전에 기록하고 학습용 목록을 내보낸다. 현재 승인 전용 `train.txt`와 `validation.txt`는 각각 0행이다. 44,265줄의 TSV는 검수용 초안이며 사전 밖 문자와 길이 제한에 걸리는 전사도 포함한다.
4. 재학습 때는 고정 분할에서 학습률(LR), 배치 정규화 설정과 학습량을 맞추고 라벨 버전만 바꿔 CER 및 단가·수량·할인 EM을 비교한다. 이번 실행에서 측정한 것은 라벨과 파일의 변경이다. 인식 성능 변화와 원본 전체 누락률은 아직 측정하지 않았다. [기존 학습 결과와 대조 실험안](OCR_학습결과_시각화와_재학습_개선안_20261120.md)
