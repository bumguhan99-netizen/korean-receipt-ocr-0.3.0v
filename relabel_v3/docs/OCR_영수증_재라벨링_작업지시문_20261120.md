# 영수증 OCR 재라벨링 작업 지시문

**사용법** ① 원본 이미지와 등록표의 해당 행을 첨부한다. ② 아래 초벌 지시문을 전달한다. ③ 검수자에게는 같은 이미지와 검수 지시문을 전달하고, 독립 판독을 마친 뒤 초벌 결과를 보여준다. 파일럿 대상과 검수 물량은 [재라벨링 계획서](<OCR_데이터셋_재라벨링_계획_20261120.md>)에 있다.

## 초벌 작업자·이미지를 볼 수 있는 AI에게 전달할 지시문

~~~text
너는 한국어 영수증 OCR의 글줄과 표 셀을 라벨링한다. 결과를 받은 사람이 원본에서 같은 영역을 잘라, 같은 문자열을 확인할 수 있게 작성하라.

[작업 입력]
배정받은 receipt_id, group_id, split, 기준 원본 이미지와 크기(W, H)를 사용하라. 선택적으로 기존 크롭과 원본으로 되돌리는 좌표 변환이 제공된다. 등록표의 ID와 분할을 그대로 유지하라. 외부 평가용으로 잠긴 23장·20거래 그룹은 별도 평가 검수 배정에서만 열고, 작업 예시는 train에서만 고른다.

[1. 원본을 읽어 영역을 찾기]
첫 판독은 기존 OCR 예측·과거 전사·자동 필드값을 숨기고 진행하라. 영수증의 위쪽부터 아래쪽까지 상품표, 양쪽 가장자리, 할인·쿠폰, 결제 부분, 하단 안내문을 확인하라. 글자가 있는 바코드 번호는 인쇄된 번호를 적고, 바코드·QR의 도형은 전사 대상에서 제외하라. 전체 사진을 확인해야 coverage를 full_pass로 표시할 수 있다. 원본이나 배정 정보를 확인할 수 없으면 확인 가능한 ID만 유지하고 coverage=not_seen, units=[], issues에 사유를 기록하라.

[2. 한 크롭과 한 전사를 대응시키기]
일반 문장은 실제 인쇄 한 줄을 한 단위로 삼아라. 두 줄 주소는 두 단위로 기록하라. 가격표는 같은 행의 상품명·수량·단가·품목금액을 눈에 보이는 셀 경계로 나누고, 같은 row_id로 연결하라. 위아래로 쌓인 가격은 값마다 하나씩 자르고 줄 순서를 남겨라. 한 셀 안에서 상품명이 두 줄이면 두 줄의 unit_id를 각각 만들고 같은 row_id와 parent_region에 연결하라. 큰 공백의 폭만 보고 일반 문장을 잘게 쪼개지 마라.

읽는 순서는 원본에서 확인해 order를 부여하라. 보통 위→아래, 같은 행은 좌→우다. 표 전체와 자식 셀을 중복 전사하지 마라. parent_region은 관련 자식을 묶는 ID로만 쓴다.

[3. 좌표 측정과 크롭 확인]
기준 프레임은 EXIF 방향을 적용한 원본이다. 좌상단이 (0,0), x는 오른쪽, y는 아래쪽이며 픽셀 경계 좌표를 쓴다. quad는 글자를 바로 읽는 방향 기준 좌상·우상·우하·좌하 네 점을 기준 원본에 표시한 값이다. 좌표를 이미지 도구로 측정하라. 정렬·축소 화면에서 작업했다면 변환을 역적용하고 원본 오버레이로 확인하라. 과거 aligned_images의 좌표를 사용할 때도 같은 절차를 적용하라.
숫자 맨 앞자리, 음수 부호, 쉼표, 마지막 받침까지 보이며 이웃 줄이 섞이지 않는지 확대해 확인하라. 제공된 크롭이 잘렸으나 원본에서 복구 가능하면 action=recrop으로 남기고 새 크롭에서 전사하라. 좌표를 측정할 수 없으면 quad=null, review=needs_review, reason=geometry_unavailable로 둔다. 크롭만 제공된 경우 원본을 본 것으로 처리하지 말고 coverage=partial로 둔다. 원본 좌표로 변환할 수 있을 때만 quad를 채운다.

[4. 보이는 문자를 적기]
text_raw에 철자·띄어쓰기·대소문자·기호를 인쇄된 그대로 적어라. 눈에 구별되는 어절 간격은 공백 하나, 열 사이 간격은 별도 셀로 처리한다. 천 단위 쉼표, 소수점, 할인 부호, 원화 기호, 별표·마스킹을 보존하라. 긴 줄이나 사전에 없는 문자도 읽히면 끝까지 적어라. 합계 계산, 사전 지식, 이전 OCR로 글자나 가려진 숫자를 보충하지 마라. 구별이 어려운 숫자·기호는 가능한 값을 임의로 고르지 말고 issues에 위치와 판독 쟁점을 적어라.

field는 주변에 인쇄된 열 제목·행 명칭을 근거로 정한다. 합계(total_amount), 실제 결제액(paid_amount), 받은 돈(tendered), 거스름돈(change)을 구분하라. 인쇄된 실결제 행이 없으면 paid_amount 단위를 만들지 마라. 문자열은 명확하지만 필드 의미가 모호하면 text_raw는 유지하고 field=unknown으로 둔다. 합산값과 인쇄 금액이 다르면 인쇄값을 보존하라.

[5. 결과 반환]
영수증당 JSON 객체 하나를 작성하라. 여러 장이면 한 줄에 한 객체인 JSONL로 반환하라. 파일 작업 권한이 있으면 배정된 새 버전 폴더에 저장하고, 채팅 작업이면 같은 형식으로 반환하라.
영수증 키는 receipt_id, group_id, split, full_image_size, frame, coverage, units, issues이다. full_image_size는 등록표의 [W,H], frame은 exif_upright다. 모르는 입력값은 null로 두고 issues에 사유를 적어라. coverage는 full_pass, partial, not_seen 중 하나다. full_pass는 작업자가 원본 전체를 훑었다는 기록이다.
각 단위의 키는 unit_id, row_id, parent_region, order, quad, field, text_raw, action, review, reason이다. unit_id는 영수증 안에서 유일해야 한다. parent_region이 없으면 null이다.
field는 merchant, item_name, quantity, unit_price, item_amount, discount, subtotal, total_amount, paid_amount, tendered, change, address, date_time, barcode_text, other, unknown 중 하나다.
action은 transcribe(읽을 수 있음), recrop(원본에서 재절단), undecided(판정 대기), ignore(글자 아님 또는 원본에서도 판독 불가) 중 하나다. transcribe에만 실제 문자열을 넣고 나머지 text_raw는 null이다. 보류 사유는 clipped, adjacent_line, ambiguous_glyph, illegible_original, non_text, geometry_unavailable 같은 짧은 값으로 남겨라.
초벌 review는 draft이며 재작업·의견 충돌은 needs_review다. verified는 사람이 실제로 원본과 크롭을 대조해 승인한 검수 기록에만 사용한다. 이전 모델의 점수와 읽을 수 없는 문자의 대체 문자열을 정답에 넣지 마라.
~~~

## 경계 사례 판정 예시

아래 문자열과 좌표는 **형식 설명용 가상 예시**다.

| 화면에서 확인한 상태 | 기록할 내용 |
|---|---|
| 같은 상품 행에 수량 `2`, 단가 `1,200`, 품목금액 `2,400`이 각 열에 보임 | 세 개의 단위로 기록하고 같은 `row_id`를 부여한다. 할인 행에 `-300`이 인쇄돼 있으면 별도 단위에 부호까지 전사한다. |
| 합계 행에는 `4,000`, 카드 결제 행에는 `3,700`이 보임 | 각각 `total_amount`, `paid_amount`로 기록한다. 계산해서 같게 고치지 않는다. |
| 크롭에서 `1,20`까지만 보이고 오른쪽 끝이 잘림 | `recrop / clipped / text_raw=null`. 원본에서 마지막 글자까지 복구한 뒤 새 크롭에서 전체를 확정한다. |
| 원본의 한 글자가 `0`인지 `O`인지 모호함 | `undecided / ambiguous_glyph / text_raw=null`. 독립 판독 후에도 읽을 수 없으면 `ignore / illegible_original`로 사유를 보존한다. |
| 마스킹된 카드번호 끝 일부 또는 `18.750`이 인쇄됨 | 보이는 별표·숫자·점을 그대로 적는다. 원문을 보존한 뒤 NFC 값만 내보내기 단계에서 생성한다. |

**반환 예시**는 가상의 800×1,200 원본 중 일부만 읽은 경우다. 단가와 할인은 서로 다른 행이며 두 번째 크롭은 부호 쪽 경계가 잘려 있다.

~~~json
{
  "receipt_id": "demo_001",
  "group_id": "demo_group_01",
  "split": "train",
  "full_image_size": [800, 1200],
  "frame": "exif_upright",
  "coverage": "partial",
  "units": [
    {
      "unit_id": "u01", "row_id": "row04", "parent_region": "items", "order": 1,
      "quad": [[420,310],[508,310],[508,338],[420,338]],
      "field": "unit_price", "text_raw": "1,200",
      "action": "transcribe", "review": "draft", "reason": null
    },
    {
      "unit_id": "u02", "row_id": "row05", "parent_region": "items", "order": 2,
      "quad": [[592,349],[695,349],[695,377],[592,377]],
      "field": "discount", "text_raw": null,
      "action": "recrop", "review": "needs_review", "reason": "clipped"
    }
  ],
  "issues": ["u02 할인 행의 왼쪽 경계를 원본에서 다시 확인"]
}
~~~

## 독립 검수자에게 전달할 지시문

~~~text
배정된 원본과 동일한 좌표 프레임에서 먼저 스스로 글줄·셀·전사를 기록하라. 그다음에 초벌 결과를 열어 비교하라. 차이는 누락, 과분할/미분할, 잘림, 전사, 부호·숫자, 필드 의미로 분류하라. 초벌과 독립 판독 결과 모두 보존하라.

학습 후보는 사람이 한 번 이상 원본과 실제 크롭으로 확인하라. 금액·수량·할인, 불일치·보류 건은 전수 이중 대조하고 일반 줄은 출처별 10%를 무작위 대조하라. 파일럿 12장은 모든 줄을 이중 판독하라. 원본 전체 평가용은 기존 박스 표시를 끈 상태에서 빠진 줄을 한 번 더 찾고 확인자를 남겨라. 기존 라벨이나 모델 예측의 다수결로 확정하지 마라.

사람이 판정을 마쳤으면 원래 unit_id, 기존값, 확정값, 변경 사유, 검수자, 검수 일시, 기준 이미지·크롭 해시를 변경 기록에 남겨라. 좌표 또는 텍스트를 수정하면 새 버전에 저장하라. 해결된 transcribe와 확인된 ignore는 verified로 기록할 수 있다. recrop·undecided 또는 좌표 미확정 건은 needs_review로 남겨라. 파일 접근이나 사람 승인 근거가 없는 AI 검수는 쟁점과 수정 제안까지만 기록하라.

인수 시 group_id의 분할 교차, 중복 unit_id, 원본 경계를 벗어나거나 면적이 0인 quad, 누락 파일·해시, 승인 문자열의 탭·줄바꿈을 검사하라. train에는 split=train, action=transcribe, review=verified, 유효 좌표와 실제 새 크롭, 인코더 통과 조건을 모두 충족한 줄만 내보낸다. 사전 밖 문자(OOV)·길이로 보류할 때도 전사와 분할을 유지하라. train 줄은 train 보류표에 두고, 검증·test의 읽을 수 있는 보류 줄은 각각 같은 분할의 외부 평가 목록에 남겨라. 원본 전체의 누락률은 독립 검수자가 전체 범위를 대조한 영수증에서 산출하라.

마지막에 원본 수, 초벌 줄 수, 승인 줄 수, 재크롭·판정 대기·제외 수, 같은 영역에 대한 판정 전 독립 전사 완전일치 수/이중 판독 수, 미해결 숫자·부호 충돌 수를 split별로 보고하라. 같은 크롭에 대한 재검수와 새로운 줄의 추가를 구분하라.
~~~
